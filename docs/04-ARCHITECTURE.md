# 04 — ARCHITECTURE

**Stack:** Swift 6, SwiftUI, SwiftData, StoreKit 2, Swift Charts, Metal (via `MTKView`/`Canvas`),
Foundation Models (optional), HealthKit (optional). **No third-party dependencies in v1.0** —
every SDK is a privacy-review liability on a health app, and a signing/CI liability with no Mac.

## 3. DATA MODEL (SwiftData)

```swift
@Model final class Profile {
    @Attribute(.unique) var id: UUID
    var name: String
    var birthYear: Int?
    var ageGroup: AgeGroup                 // underFive, fiveToTwelve, thirteenPlus
    var amblyopicEye: Eye                  // left, right, unknown
    var wearsCorrection: Bool
    var isKidsMode: Bool
    var createdAt: Date
    var calibration: CalibrationProfile?
    @Relationship(deleteRule: .cascade) var sessions: [SessionRecord]
    @Relationship(deleteRule: .cascade) var assessments: [AssessmentResult]
    var preferences: PreferencesBlob       // Codable struct
}

@Model final class CalibrationProfile {
    var screenPointsPerCM: Double          // from device model lookup, user-verifiable with a card
    var viewingDistanceCM: Double
    var anaglyphAmblyopicFilter: AnaglyphFilter   // red or cyan
    var redLeakIntoCyan: Double            // 0…1 crosstalk coefficients
    var cyanLeakIntoRed: Double
    var colorVisionOK: Bool
    var calibratedAt: Date
}

@Model final class SessionRecord {
    var id: UUID
    var startedAt: Date
    var endedAt: Date?
    var plannedSeconds: Int
    var actualSeconds: Int
    var completed: Bool
    var endedReason: EndReason             // completed, userStopped, fatigue, cap, interrupted
    var track: Track                       // monocular, dichoptic, game, assessment
    @Relationship(deleteRule: .cascade) var trials: [TrialRecord]
}

@Model final class TrialRecord {
    var exerciseID: String
    var timestamp: Date
    var correct: Bool
    var responseTimeMS: Int
    var difficultyValue: Double            // the staircase dimension's value on this trial
    var parametersJSON: Data               // full ExerciseParameters snapshot
}

@Model final class AssessmentResult {
    var date: Date
    var acuityAmblyopic: Double?           // logMAR-style
    var acuityFellow: Double?
    var contrastCurve: [Double]            // 4 spatial frequencies
    var binocularBalance: Double?          // 0…1
    var stereoArcmin: Double?
    var blockIndex: Int                    // which 4-week block
}
```

**Storage:** local SwiftData only in v1.0. CloudKit sync in v1.1 behind a settings toggle — adding it
in v1.0 forces "data linked to you" answers on the App Privacy form and complicates review.

## 4. RENDERING STRATEGY

Three tiers, chosen per exercise:

| Tier | Use | API |
|---|---|---|
| **SwiftUI views** | UI, simple targets, games with < ~50 sprites | Plain SwiftUI + `TimelineView(.animation)` |
| **`Canvas`** | Dot fields, Glass patterns, tracing paths, most stimuli | SwiftUI `Canvas` with `GraphicsContext` |
| **Metal / `CIFilter` chain** | Gabors, gratings, anaglyph compositing, contrast rebalancing | Custom fragment shaders |

**Everything is generated procedurally.** No stimulus is a bundled PNG. That is how we ship < 25 MB
against the reference app's 81.4 MB (`14` R13).

**Anaglyph compositing pipeline (Phase 7), per frame:**

```
1. Render amblyopic-eye layer  → texture A (single channel, luminance)
2. Render fellow-eye layer     → texture F (single channel, luminance)
3. Apply contrast rebalance:   F' = 0.5 + (F - 0.5) * contrastFellow
4. Crosstalk cancellation:     A'' = A - cyanLeakIntoRed  * F'
                               F'' = F' - redLeakIntoCyan * A
   (clamp to [0,1]; log clipping — if it clips often, the user must recalibrate)
5. Composite by filter assignment:
      amblyopic = red  →  RGB = (A'', F'', F'')
      amblyopic = cyan →  RGB = (F'', A'', A'')
6. Apply the shared/fusion-lock layer to all three channels (drawn white)
```

**Angular size correctness.** `ScreenGeometry` maps device model → physical PPI (a static table;
`UIScreen.nativeBounds` + model identifier). Combined with `viewingDistanceCM`:
`sizeInPoints = 2 * distanceCM * tan(angleDeg/2 * .pi/180) * pointsPerCM`.
Without this, "1 cycle per degree" is meaningless and every threshold we report is noise. This is the
single biggest technical quality gap versus every competitor.

## 5. CONCURRENCY & PERFORMANCE

- Swift 6 strict concurrency. `@MainActor` on all view models; `SessionRunner` is a `@MainActor`
  `@Observable` class.
- Stimulus generation on a dedicated `TaskGroup` off the main actor; only the final texture crosses back.
- Target **120 fps on ProMotion, 60 fps floor.** Motion and timing tasks that drop frames produce
  invalid psychophysical data — treat a dropped frame as a discarded trial, and log it.
- `CADisplayLink` drives timing-critical exercises; never `Timer`.
- Memory ceiling 150 MB during a session.

## 6. SAFETY SUBSYSTEM (cross-cutting, `Core/Safety`)

| Component | Behaviour |
|---|---|
| `FlickerGuard` | Compile-time and runtime assertion that no `temporalRate` exceeds 3.0 Hz and no stimulus inverts full-field luminance. Unit-tested against every registered exercise. |
| `BreakScheduler` | Inserts a mandatory 20-second break card every 20 minutes of cumulative session time. Non-skippable for under-13 profiles. |
| `FatigueMonitor` | Always-visible "My eyes feel tired" control. Tapping it ends the session immediately, logs `endedReason = .fatigue`, and shows rest guidance. **Never encourages continuing.** (`14` R4) |
| `SessionCap` | Under-13: hard 20 min/day cap, parent-gated override. All ages: 30 min/session ceiling. |
| `EscalationRule` | Two consecutive 4-week blocks without measurable improvement → non-dismissible professional-referral card. |
